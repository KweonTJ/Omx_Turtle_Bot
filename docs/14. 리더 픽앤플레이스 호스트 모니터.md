# 리더 픽앤플레이스 호스트 모니터

2026-10-13 / ROS 2 Humble / `omx_turtle_ws/src/omx_leader_monitor`.
새 임무 기준은 [2단 정리대 ID 기반 계획](<./13. 2단 정리대 ArUco ID 기반 픽앤플레이스 계획.md>)이다.

## 화면과 실행 범위

- 왼쪽 큰 화면: RViz를 내장한 리더/매니퓰레이터 3D, 팔 중심/전체 시점.
- 왼쪽 아래: 실제 상태 토픽의 단계, 검출 ID·층·좌표, 요청 ID와 일치 여부.
- 오른쪽: 그리퍼 카메라 한 개의 전체 프레임, 최근 30초 J1~J4 관절각 그래프, 호스트 요청 기록.
- 관절·영상·미션·검출이 기본 2초 이상 없으면 지연/무효로 표시한다.
- 요청은 기록이지 실행 ACK가 아니다. 같은 request_id 재송신은 카운트를 늘리지 않는다.
- GUI/브릿지는 읽기 전용이다. 실제 로봇 bringup, 정책 추론, trajectory, 그리퍼, cmd_vel 명령을 시작하지 않는다.
- 창을 닫으면 해당 launch가 시작한 RSP·브릿지·데모만 함께 종료한다.

## 빌드 및 호스트 셸 실행

```bash
cd /home/ktj/omx_turtle_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
colcon build --symlink-install --packages-select omx_leader_monitor
source install/setup.bash

# 이미 아래 계약으로 토픽이 브릿지되는 호스트: 실데이터 수신 대기
bash src/omx_leader_monitor/scripts/run_leader_pick_place_monitor.sh --domain 16

# 실제 로봇 없이 UI만 확인 (domain 223, localhost, 전용 토픽 강제)
bash src/omx_leader_monitor/scripts/run_leader_pick_place_monitor.sh --demo
```

16은 호스트 기본값이며 실제 설정으로 변경할 수 있다. 소스 로봇 domain은 자동 추정하지 않는다.
직접 launch는 `ros2 launch omx_leader_monitor leader_monitor.launch.py host_domain:=16`.
호스트의 그래픽 로그인 세션에서 실행한다. `--fullscreen`은 최대화, `--compressed`는 압축 영상 수신이다.

별도 브릿지가 없다면 **실제로 확인한 로봇 domain**을 입력한다.

```bash
read -r -p '확인한 리더 ROS_DOMAIN_ID: ' leader_domain
ROS_LOCALHOST_ONLY=0 bash src/omx_leader_monitor/scripts/run_leader_pick_place_monitor.sh \
  --domain 16 --bridge-from "$leader_domain"
```

`topic_bridge.py`는 서로 다른 두 ROS Context의 domain을 사용해 허용된 텔레메트리만 단방향 복사한다.
역방향·제어 목적지와 중복 목적지를 허용하지 않는다. 동일 domain에서는 브릿지 없이 리매핑한다.
기존 브릿지와 새 브릿지를 동시에 연결하여 중복 발행하지 않는다. DDS 검색/방화벽/네트워크는 별도 확인한다.
본 도구는 네트워크 인증·암호화 경계를 제공하지 않으므로 신뢰할 수 있는 로봇 네트워크에서 사용한다.

## 토픽 계약

| 리더 소스 기본값 | 호스트 수신 토픽 | 타입 |
|---|---|---|
| `/joint_states` | `/leader_monitor/input/joint_states` | `sensor_msgs/msg/JointState` |
| `/eef_camera/image_raw` | `/leader_monitor/input/eef/image_raw` | `sensor_msgs/msg/Image` |
| `/eef_camera/image_raw/compressed` | `/leader_monitor/input/eef/image_raw/compressed` | `sensor_msgs/msg/CompressedImage` |
| `/rl_control/status` | `/leader_monitor/input/status` | `std_msgs/msg/String` |
| `/target/aruco_pose` | `/leader_monitor/input/aruco_pose` | `geometry_msgs/msg/PoseStamped` |
| `/target/valid` | `/leader_monitor/input/target_valid` | `std_msgs/msg/Bool` |
| `/target/selected_info` (신규 계약) | `/leader_monitor/input/target_info` | `std_msgs/msg/String` JSON |
| 호스트 요청 발행기 (구현 예정) | `/leader_monitor/host_request` | `std_msgs/msg/String` JSON |

리더 토픽명은 `config/bridge_topics.yaml`에서 수정한다. 호스트 요청은 호스트에서 발행하므로
리더→호스트 텔레메트리 브릿지 목록에 넣지 않는다. GUI는 BEST_EFFORT 구독으로 reliable/best-effort
발행기를 모두 받는다. 요청은 volatile/transient-local 구독을 함께 두어 재전송과 late-join을 처리한다.
이미지 transport 두 개 중 하나만 연결하며 압축 토픽 발행기는 이 패키지가 시작하지 않는다.

새 요청 관찰 메시지 예시 (실제 로봇 명령 아님):

새 발행기는 reliable/transient-local depth 1을 권장한다. volatile 발행기에서는 보조
transient-local 구독에 QoS 경고가 날 수 있지만 volatile 주 구독으로 계속 수신한다.

```json
{"request_id":"host-0001","object_id":3,"command":"PICK_PLACE","issued_at":"2026-10-13T23:30:00+09:00"}
```

`command`: PICK / PLACE / PICK_PLACE / CANCEL. `object_id`는 선택한 마커 ID와 일대일로 사용한다.
취소도 대상 ID와 새로운 request_id를 가진 **관찰 기록**이며 GUI가 취소 명령을 실행하지 않는다.
`config/host_request.schema.json` 참조. 요청 송신기는 중복 아닌 요청마다 ID를 새로 발급해야 한다.
카운트는 현재 GUI 세션에서 관찰한 고유 요청 수이며, 전체 시스템의 누적 성공 횟수가 아니다.
화면 최근 3개, 내부 최근 8개, 세션 중복 방지 ID 최대 10,000개를 보관한다.

검출 메타데이터 예시 (위치 단위 m, 예시 좌표이지 고정 목표 아님):

```json
{"marker_id":3,"valid":true,"shelf_level":2,"frame_id":"base_link","position":[0.24,-0.04,0.26]}
```

`shelf_level`은 생략/null이면 미확인, 있으면 1 또는 2다. 기존 Vision은 이 메시지를 아직
발행하지 않는다. 호스트 요청 ID를 검출 ID처럼 복사해 보여주지 않으며, ID 없는 Pose만으로
물체 번호를 추정하지 않는다. 무효 시에도 동일 필드와 `valid:false`를 발행하고, timeout은 별도로 적용한다.

## 영상·TF·지연 표시

- 같은 카메라 전체 프레임을 유지한다. 실제 접근에 따라 물체가 커지는 것을 관찰한다.
- optical frame 마커 거리와 valid가 모두 최신이면 22 cm 이내에 `근접 관찰`, 28 cm 밖에
  `전체 장면`을 표시한다(최소 유지 0.7초). 자동 크롭·다른 카메라 전환·목표 추적 확대는 없다.
- 이 거리는 카메라→현재 마커 거리이며 그리퍼 파지 여유 거리나 요청 ID 인증이 아니다.
- 실측 관절 입력을 표시용 `robot_state_publisher`에만 전달한다. 모델은 재질 분리 exporter를 사용한다.
- TF/description은 `/leader_monitor/visualization/{tf,tf_static,robot_description}`로 격리한다.
- 관절 일부가 없거나 오래되면 3D를 반투명 처리하고 마지막/미완성 자세 경고를 표시한다.
- 그래프는 관절별 만료 시 끊긴다. 그리퍼 왼쪽 joint의 mm 값은 양손 사이 폭이 아니다.
- freshness는 호스트의 **수신 후 경과 시간**이다. 원본 header stamp/영상 지연의 종단 간 보장은
  아니며, 네트워크에 밀린 오래된 메시지가 새로 도착하는 문제는 동기화·센서 검증 계층에서 해결해야 한다.
- 상태 단계는 로봇 보고값이며 앞 단계 성공을 GUI가 추론하거나 실행을 보증하지 않는다.

데모는 `/leader_monitor/demo/*`에 합성 영상/관절/상태를 발행한다. 학습 모델 추론, 물리 파지,
실카메라 영상 또는 새 선반 미션 성공 결과가 아니다. `--demo`와 `--bridge-from` 동시 사용은 거부한다.
실데이터 미수신 시 데모로 자동 대체하지 않는다.

```bash
colcon test --packages-select omx_leader_monitor --event-handlers console_direct+
colcon test-result --verbose
```

UI 통합 검사는 `test/runtime_smoke.py`에 별도 제공한다. 실제 제어를 실행하지 않고 격리 domain에서
합성 raw/compressed 수신, 요청 재전송 중복 방지, 송신 중단 후 지연 전환을 검사한다.
실제 브릿지 네트워크·카메라 인쇄 마커·ID별 선택 제어·신규 RL 정책·팔로워 배치는 아직 통합 검증 전이다.

진단용 launch 인수 `diagnostics_path:=/tmp/monitor.json`을 지정하면 수신 상태 JSON과
초기 3D framebuffer 1장(`.render.png`)을 저장한다. 기본 실행에서는 파일 저장을 하지 않는다.

RViz 내장 초기화 및 실행 모델은 설치된 Humble 헤더와
[공식 VisualizationFrame](https://github.com/ros2/rviz/blob/humble/rviz_common/src/rviz_common/visualization_frame.cpp),
[VisualizationManager](https://github.com/ros2/rviz/blob/humble/rviz_common/src/rviz_common/visualization_manager.cpp)를 기준으로 한다.
