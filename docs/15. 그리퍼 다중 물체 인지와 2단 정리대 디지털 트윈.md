# 그리퍼 다중 물체 인지와 2단 정리대 디지털 트윈

작성: 2026-10-14. 구현 위치: `/home/ktj/omx_turtle_ws/src`.
학습 workspace에는 이번 소스·모델을 만들지 않는다.

## 1. 역할 경계

- 그리퍼 카메라 한 대가 관찰 자세에서 **ID 1~4를 한 번에 본다**.
- 호스트는 인지할 ID를 선택한다. 같은 ID라도 현재 영상에서 다시 구한 위치를 사용한다.
- 가까이 가서 나머지 마커가 화면 밖으로 나가더라도 선택한 ID만 계속 관측할 수 있다.
- 카메라 패키지는 **인지 전용**이다. 마커 중심 자세는 파지점·접근 경로·도달성 판정이 아니다.
- 팔 관찰 자세/움직임/파지/인출/놓기와 가림 중 동작 판단은 앞으로 만들 OMX RL 모델·제어기의 책임.
- 이번 작업은 기존 v4 정책을 수정·학습하지 않고 실제 모터를 움직이지 않는다.

## 2. 마커와 카메라

| 항목 | 새 설정 |
|---|---|
| 패키지/노드 | `omx_eef_vision` / `multi_object_vision_node` |
| Launch/설정 | `shelf_perception.launch.py` / `config/shelf_perception.yaml` |
| Dictionary / ID | `DICT_4X4_50` / 1, 2, 3, 4 |
| 인쇄안 | 검은 정사각형 40 mm, 흰 여백 별도, A4 100% |
| 영상 입력 | `/eef_camera/image_raw`, `/eef_camera/camera_info` |
| 새 camera-only 시작 모드 | 640×480, YUYV → rgb8, 변경 가능 |
| 기본 실행 | 기존 영상 구독, 카메라 드라이버 중복 시작 안 함 |
| 좌표 | 카메라 optical 및 `base_link`; 마커 중심, m 단위, xyzw quaternion |

[인쇄용 SVG](<../omx_eef_vision/markers/01. ArUco ID 1-4 인쇄용.svg>)를
페이지 맞춤 없이 출력하고 검은 부분 한 변과 100 mm 기준선을 재측정한다.
실제 변 길이를 `marker_size_m`에 넣고 `marker_size_confirmed: true`로 바꾼다.
각 물체의 카메라를 향한 평면에 서로 다른 ID를 한 장씩 부착한다.
선반 층이나 고정 위치에 ID를 붙여 물체 ID처럼 해석하지 않는다.

CameraInfo는 **현재 raw 영상과 해상도·optical frame이 일치**해야 한다.
기존 320×240 보정은 보존하지만 새 640×480 영상에 자동 확대 적용하지 않는다.
CameraInfo가 없으면 ID/픽셀 코너는 제공하고 3D 유효값은 제공하지 않는다.
plumb_bob/rational_polynomial만 지원하며 fisheye, ROI, binning 영상은 별도 보정/처리 필요.
실제 camera-to-arm 외부 보정과 관절 TF를 확인하고 `extrinsics_confirmed: true`로 바꾼다.
디지털 트윈 표시 TF를 실기 보정값으로 대신 사용하지 않는다. 설정 변경 후 노드를 재시작한다.

네 마커가 동시에 보이는지는 실제 렌즈 시야각·거리·팔 관찰 자세·가림에 달려 있다.
해상도를 올리는 것만으로 시야각이 넓어지거나 어디서든 인지/파지할 수 있는 것은 아니다.

## 3. 실행 (인지 전용)

```bash
cd /home/ktj/omx_turtle_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select omx_eef_vision turtlebot3_manipulation_description
source install/setup.bash

# 카메라 토픽이 이미 있다면
ros2 launch omx_eef_vision shelf_perception.launch.py

# 카메라 장치가 연결된 컴퓨터에서 드라이버까지 시작할 경우 (택일)
# 실제 장치 경로, 지원 해상도, 해당 해상도의 보정 파일로 변경
ros2 launch omx_eef_vision shelf_perception.launch.py \
  start_camera:=true video_device:=/dev/video0 width:=640 height:=480 \
  camera_info_url:=file:///absolute/path/eef_camera_640x480.yaml
```

`start_camera:=true`에는 `ros-humble-v4l2-camera`가 필요하다.
현재 개발 호스트에서는 드라이버 패키지와 `/dev/video*`가 확인되지 않아 실영상 시험은 하지 않았다.
정확한 보정 파일이 아직 없으면 `camera_info_url`을 비워 **2D 검출부터** 확인할 수 있다.
실제 카메라 장치는 `/dev/v4l/by-id/...`의 고정 경로 사용을 권장한다.
기존 `omx_turtle.launch.py`는 제어기/초기 팔 동작을 시작하므로 인지 시험용으로 실행하지 않는다.

선택은 인지 메타데이터일 뿐 팔 명령이 아니다. 호스트와 인지 노드가 다른 ROS domain이면
이 입력 토픽을 별도 허용 브릿지로 전달해야 한다. 이번 작업은 자동 양방향 브릿지를 만들지 않는다.

```bash
ros2 topic pub --once /perception/target_request std_msgs/msg/String \
  '{data: "{\"request_id\":\"scan-001\",\"command\":\"SELECT\",\"object_id\":3}"}'
ros2 topic echo /perception/objects
ros2 topic echo /perception/selected_info
# 취소 및 최초 4개 관측 초기화
ros2 topic pub --once /perception/target_request std_msgs/msg/String \
  '{data: "{\"request_id\":\"clear-001\",\"command\":\"CLEAR\"}"}'
```

각 새 요청에는 새 request_id를 사용한다. 동일 요청 재전송은 무시하고 내용이 달라진 ID 재사용은
거절한다. 세션 최대 4096개를 넘으면 새 요청을 거절한다. PICK/PLACE 명령은 수신하지 않는다.
기존 GUI의 `/leader_monitor/host_request`는 관찰 전용 계약으로 그대로 보존한다.

## 4. 출력 계약 (schema_version=1)

| 토픽 | 타입 | 의미 |
|---|---|---|
| `/perception/objects` | String JSON | 현재 프레임의 모든 검출, ID/코너/중심·품질·3D 가능 여부 |
| `/perception/selected_info` | String JSON | request_id·marker_id·valid·reason·촬영시각·선택 좌표를 한 메시지로 제공 |
| `/perception/selected_pose` | PoseStamped | 선택 ID의 안정된 마커 중심 자세. 무효 프레임에는 발행하지 않음 |
| `/perception/selected_valid` | Bool | 모니터링용 보조 유효 신호 |
| `/perception/status` | String JSON | 대기·추적·실패 사유 |
| `/perception/debug_image` | Image bgr8 | 전체 화면, 모든 ID와 선택 ID 강조. 자동 crop 없음 |

`objects`: `fresh`, `stamp_ns`, `camera_frame`, `image_size`, `overview_ready`, `objects[]`.
각 항목은 `marker_id`, `expected`, `corners_px`, `center_px`, `perimeter_px`, `duplicate`,
`usable_2d`, `pose_valid`, `pose_reason`을 가진다. 품질을 통과한 PnP 결과에는
`camera_position`, `camera_orientation_xyzw`, `reprojection_error_px`가 추가된다.
이 카메라 좌표도 실측 미확인 크기에 의한 **진단용 추정치**일 수 있다.
외부 보정/TF까지 통과하면 `position`, `orientation_xyzw`, `frame_id`가 추가된다.
`pose_valid`는 단일 프레임의 인지 품질이며 충돌 안전, 파지 성공 또는 제어 허가를 뜻하지 않는다.

`selected_info.valid=true`는 최초 4개 동시 검출과 요청 후 선택 자세가 3프레임 안정된 경우다.
좌표 급변 시 새 관측으로 안정 카운트를 다시 시작하며, 과거 위치를 유효하게 유지하지 않는다.
이미지의 acquisition stamp 기준 TF를 사용하고 latest-TF fallback을 하지 않는다.
카메라·ROS 시계 동기화 필요. 영상 최대 나이 0.4초, 수신 watchdog 0.5초, 검사주기 0.1초.
보정 변경/타임아웃은 전체 관측 준비를 초기화한다. 재시작 후에도 최초 4개 관측이 필요하다.

소비자는 **선택 JSON의 request_id·marker_id·valid·stamp_ns를 함께 검사**하고 자체 watchdog을
가져야 한다. 노드 종료/네트워크 단절 후 마지막 PoseStamped를 계속 사용하는 것은 금지한다.
층 번호는 아직 자동 추론하지 않으며 `shelf_level=null`이다.
기존 호스트 GUI/브릿지의 `/target/*` 계약으로 무조건 remap하지 않는다.
3D 인지 메타데이터와 UI 연결은 후속 통합 시 별도 adapter로 명시한다.

제조자는 현재 상품정보 고시/사용자 라벨이 기현산업(주), 상세 이미지에는 대현화학공업(주)로
서로 다르게 적혀 있다. 따라서 상세 이미지에서 실물 미측정 두께나 적층 간격을 확정하지 않는다.

모델: 앞이 열린 상자 2개, 바닥·네 다리·낮은 전면 턱·좌우/후면 타공 패널·층 바닥 TF.
X는 깊이, Y는 폭, Z는 위쪽이다. 개방면은 -X이며 리더 정면 +X 쪽에 둔다.
타공은 반복 사각 슬롯, 곡면/테이퍼/체결홈/판·다리 두께는 근사다.
collision은 타공 구멍까지 막은 보수적 바닥·벽·다리 box이며 **planning scene 자동 등록 없음**.
질량/관성·마찰을 추측해서 넣지 않았으므로 Gazebo/MuJoCo 동역학 검증용으로 바로 쓰지 않는다.

## 6. 검증과 남은 범위

- pytest 26 통과, 기존 copyright 검사 1 skip. 신규 소스 flake8/pep257 통과.
- 격리 localhost/domain 228에서 실제 ROS 메시지 + 합성 4마커 영상 + 시험용 CameraInfo/TF 검증.
  ID 선택 변경, 선택 물체만 남음, 소실/중복, 보정 해상도 불일치, 실측확인 미완료,
  TF 누락, stale image, timeout, 제어 토픽 미생성 검사 통과.
- 정리대 156/168/180 mm 간격에서 모델 외곽치수·개방면·층 바닥 프레임·collision primitive 검사.
- USB 실영상 검출률/정확도·실기 카메라 캘리브레이션·실제 도달/충돌 시험은 아직 하지 않았다.
- 새 OMX 정책 학습, 인지 관측 입력 연결, 파지/팔로워 전달, 호스트 브릿지 통합은 별도 작업이다.
