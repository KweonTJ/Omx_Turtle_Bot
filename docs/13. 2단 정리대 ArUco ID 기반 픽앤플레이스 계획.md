# 2단 정리대 ArUco ID 기반 픽앤플레이스 계획

기준: 2026-10-13 사용자 사진·요구 변경. 기존 서랍 열기 계획을 대체한다.
이 문서는 새 임무의 설계 기준이며, 실제 제어·새 학습 모델의 완료 보고가 아니다.

## 1. 변경된 목표

- 다이소 정리대 2개를 적층하여 2개 층을 만든다.
- 약 4개 물체에 각각 서로 다른 ArUco ID를 부착한다.
- 호스트는 **물체 ID**를 지정한다. 층이나 고정 좌표를 지정하지 않는다.
- 리더 베이스는 고정한다. 매니퓰레이터와 그리퍼 카메라로 요청한 물체를 찾고 접근한다.
- 물체의 ID가 같아도 배치가 바뀌면 **이번 검출 위치**로 접근한다. `ID → 고정 XYZ` 테이블은 사용하지 않는다.
- 파지 후 선반 밖으로 물체를 꺼내 옆 팔로워 로봇의 수납 위치에 놓는 기존 최종 목표를 유지한다.
- 기존의 서랍 번호 선택·손잡이 파지·서랍 열기 단계는 새 임무에서 제외한다.

“어느 위치든”은 인식 가능하고, 관절 한계·도달 거리·충돌 없는 접근 및 인출 경로를
모두 만족하는 **검증된 작업 영역 안**을 뜻한다. 두 층 전체를 현재 팔이 다 잡을 수 있다고
아직 보장하지 않는다. 실패 시 베이스를 자동 이동시키는 것은 이번 범위가 아니다.

## 2. 실물 정리대 기준

사용자 제공 제품 라벨을 읽은 값이며 외부 쇼핑몰 사양으로 대체하지 않는다.

| 항목 | 사진에서 확인한 값 |
|---|---|
| 제품 | 다용도 적층 정리대 소형 / 멀티정리대(소) |
| 품번 | 1001965 |
| 1개 외부 크기 | 약 폭 365 × 깊이 285 × 높이 180 mm |
| 1개 내부 크기 | 약 폭 332 × 깊이 245 × 높이 152 mm |
| 구조 | 전면 개방, 좌우·뒤 벽과 바닥, 적층 구조 |
| 구성 | 2개 적층, 물체 약 4개 |

단순 높이 합은 360 mm지만 적층 결합부 때문에 **실제 총높이·층간 바닥 높이 차는
실측해야 한다.** 내부 공칭 높이는 카메라/팔이 안전하게 통과하는 높이와 같지 않다.
사진의 제품·가격 바코드는 작업용 ArUco 마커가 아니다.

## 3. ID와 위치를 연결하는 방법

1. 호스트 요청에 고유 `request_id`, `object_id`, 동작을 포함한다.
2. 한 영상에 여러 마커가 보여도 요청 ID만 목표 후보로 선택한다.
3. 카메라 보정값과 **실제 인쇄한 마커의 검은 사각형 한 변 길이**로 자세를 구한다.
4. 이미지 시각의 관절 TF와 hand-eye 보정으로 마커 자세를 로봇 기준 좌표로 변환한다.
5. 마커 부착점과 실제 파지 중심의 상대 위치·방향을 적용해 파지 목표를 계산한다.
6. 접근 중 같은 ID를 계속 추적하고, TF/검출 만료·큰 위치 점프·ID 변경 시 정지/재탐색한다.

변환 관계: `T_base_grasp = T_base_eef(t_image) × T_eef_camera × T_camera_marker × T_marker_grasp`.
마커 중심과 파지 중심은 다르다. ID별 물체 크기/파지 오프셋은 등록할 수 있지만,
월드 위치를 ID별 고정값으로 등록하지 않는다.

그리퍼 카메라 **한 개**로 전체 탐색부터 근접 관찰까지 진행한다. 접근하며 물체가 실제 영상에서
커진다. 처음 본 위치만 저장해 끝까지 맹목적으로 움직이거나, 중앙 디지털 확대를 대상 추적으로
취급하지 않는다. 가림·초점거리 한계로 검출이 끊기면 안전 정지 후 재관찰하는 경로가 필요하다.

4관절 팔에서는 임의 XYZ와 임의 RPY를 동시에 모두 강제할 수 없다. 관절1 회전·작업영역에 맞는
파지 방향을 선택하고 카메라 시야 및 가능한 pitch 조건을 유지하도록 설계·검증한다.

## 4. 새 미션 상태

요청 대기 → 요청 ID 탐색 → 위치/도달성 확인 → 선반 입구 접근 → 물체 접근 → 파지 확인
→ 선반 밖 인출 → 팔로워 수납 위치 접근 → 놓기 확인 → 빈 팔 복귀 → 완료.

- 요청 ID가 없으면 다른 ID를 대신 집지 않는다.
- 목표가 보이지 않으면 제한된 안전 탐색만 수행하고 timeout 결과를 보고한다.
- 선반 안에서 바로 옆으로 전달 궤적을 만들지 않는다. 인출 후 전환한다.
- 다른 물체, 벽, 아래층 천장, 입구 턱, 카메라와 케이블의 충돌 여유를 확인한다.
- 파지/해제 성공은 그리퍼 명령 완료만으로 확정하지 않는다.
- 호스트 요청 수신, 로봇 접수 ACK, 실행 상태, 완료 결과를 별개로 관리한다.
- 팔로워가 없거나 수납 자세가 만료되면 놓기를 진행하지 않는다.

## 5. 현재 구현과 아직 없는 기능

| 영역 | 현재 확인 / 남은 일 |
|---|---|
| 기존 정책 | `arm_delivery_pitch_hold_v4` PICK/PLACE 경로. 새 선반 임무 성공 근거 없음 |
| 기존 비전 설정 | `DICT_APRILTAG_36h11`, `marker_id: 0`, `accept_any_marker: true`, 40 mm 설정 |
| 요청 ID 선택 | 기존 임의 마커 허용 설정만으로는 보장 불가. 요청과 검출 ID 연결 구현 필요 |
| 실물 마커 | Dictionary·실제 ID·크기 미확정. UI 데모의 1~4는 예시 번호 |
| 선반 모델/학습 | 아직 미구현. 사진 치수는 모델링 입력이며 충돌 검증 완료값이 아님 |
| 호스트 모니터 | 요청 ID·검출 ID·층·좌표·카메라·관절·상태를 표시하는 읽기 전용 GUI |
| 검출 메타데이터 | `/target/selected_info` 신규 계약. 기존 Vision은 아직 발행하지 않음 |
| 실제 명령 계약 | 기존 `/rl_control/command`는 문자열 동작이며 ID를 담지 않음. 별도 설계 필요 |

`ArUco`라는 노드 이름과 실제 Dictionary는 다를 수 있다. 인쇄 마커와 검출기를 일치시키고,
다중 물체를 켠 채 기존 `accept_any_marker: true` 설정으로 실물 자동 파지를 시작하지 않는다.
이번 변경은 기존 비전 설정·하드웨어 launch·정책 파일을 수정하거나 실물 팔을 구동하지 않는다.

## 6. 학습·배포 순서

1. 마커 종류/크기와 실물 배치 실측, 카메라 보정 및 TF 검증.
2. `omx_turtle_ws`에 2단 정리대·팔로워 수납면의 디지털 트윈과 충돌 모델 구성.
3. 네 물체 동시 인식, ID 선택, 위치 이동·층 변경·가림·미검출 시험.
4. 고정 베이스에서 각 층 좌우/앞뒤 격자 도달성 검사. 검증 범위 밖은 명시적으로 거절.
5. 학습에 필요한 환경만 `omx_train_ws`로 연결. 위치/층/자세·마찰·센서 오차를 변화시켜
   선반 접근·파지·인출·전달·놓기를 단계적으로 학습하고 평가한다.
6. 새 계열 이름은 `omx_turtlebot3`, 후속 버전은 `omx_turtlebot3_vn`.
   기존 v4와 관측/행동 계약이 같다고 가정하지 않는다.
7. 검증한 ONNX와 관측 순서·정규화·action scaling·관절 순서·제한·checksum·평가 결과를
   묶어 `omx_turtle_ws`로 배포한다. 목적지 디렉터리와 런타임 계약은 배포 시 확정한다.
8. fake hardware → 저속 무부하 → 단일 물체 → 4개 혼합 배치 순으로 실기 검증한다.

평가는 총 성공률뿐 아니라 **잘못된 ID 파지 0건**, 층/영역별 성공률, 미검출·도달불가 거절,
충돌·낙하·오선택·수동 개입, timeout 정지를 별도로 기록한다. 이 문서 작성으로 학습을 시작하거나
새 모델이 생성된 것은 아니다.
