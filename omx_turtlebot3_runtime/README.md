# omx_turtlebot3 v6 실물 제어기

리더 로봇의 고정 베이스 픽앤플레이스를 위한 실물 제어기다. 관절 엔코더와 그리퍼 위치·전류,
그리퍼 RGB 카메라의 ArUco 관측으로 69차원 입력을 구성하고, v6의 4차원 보정 출력을
단계별 기준 경로에 더한다. ONNX 출력 자체를 관절각으로 보내지 않는다.

기본 실행은 읽기 전용이다. 실물 접촉·안착 추정의 임계값, 관절 영점·방향, 카메라 외부
보정과 장면 정렬을 검증하기 전에는 `--execute`가 거부된다. 배포 및 소프트웨어 테스트
통과는 실제 집기 성공을 뜻하지 않는다. 모델 체크포인트는 v6 그대로이며 새 학습은 하지 않았다.

## C++ ONNX 제어 실행

기존 하드웨어 Stay 런치에 붙이는 실물 mp_control + ONNX 진입점은
`ros_policy_pick_place.launch.py`다. 기본값은 monitor이며 `execute:=true`에서 선택한 마커의
미션을 한 번 시작한다. `marker_id:=1`은 ID 1의 목표 좌표와 모델의 대상 슬롯을 함께 선택한다.
joint4 연동 보상 설정과 measured Stay·실제 마커·활성 제어기를 검사한다.
전개 명령은 0.35초 이동·0.05초 안정화 간격으로 실행하며 진행 중인 구간을 반복 초기화하지 않는다.
joint3 구간 이동 한도는 0.25 rad이며, 이송 joint1은 홀수·짝수 집기 모두 −90°다.
`gripper_down_joint4_offset_rad:=0.20`을 기본 적용해 최종 손목 목표를 약 −0.35 rad로
조정한다. 실물에서는 −0.75 rad가 파지점을 높였으므로 반대 방향을 사용한다.
`pause_before_grasp:=true`는 팔 전개 후 집기 높이를 확인할 때 사용하며,
`/mp_control/continue_grasp`에 Bool true를 보내면 같은 자세에서 집기를 이어간다.
이송은 집기 → Z 높이·그리퍼 pitch를 유지하는 후퇴 → 90° 회전 → 바로 그리퍼 열기 → Stay 복귀 순서다.
`handoff_retract_hold_z: true`는 집은 자세를 기준으로 joint2·3·4를 함께 계산한 36개 경유점을
사용한다. joint3 진행량은 기존 확인한 몸쪽 방향 +0.65 rad이며, joint2를 고정하는 방식은 사용하지 않는다.
각 점과 점 사이의 높이 유지도 URDF 행렬 FK와 대조한다. 관절 피드백으로 계산한 Z가 5 mm 이상
벗어나면 대기 중인 궤적을 현재 자세 유지 명령으로 교체하고 그리퍼를 열지 않는다.
`handoff_lower_before_release: false`이므로 회전 후 추가 하강은 실행하지 않는다.
`pause_before_rotate:=true`는 후퇴 자세 확인용이며 `/mp_control/continue_handoff` Bool true로 회전을 이어간다.
관절 전개가 시작된 뒤에는 같은 경로를 유지하며 마커 가림 때문에 초기 접근 단계로
되돌아가지 않는다. 실시간 관절 피드백과 취소·추론 입력 중단 감시는 유지한다.
joint4 관절각을 고정하지 않고 자세에 맞게 연동한다. 높이 유지 후퇴·회전 구간은 ONNX 보정이
joint2·3·4의 높이 제약을 깨지 않게 제한한다. 이 ROS 진입점은 mp_control 기준 경로에 ONNX
보정을 더하는 시험 모드이며, 원본 학습 환경의 20 ms 제어 루프와 동일한 실행은 아니다.

`runtime_cpp` 또는 `--backend cpp_onnx`로 [v6 C++ 제어 패키지](../omx_turtlebot3_control_cpp/README.md)를
선택한다. 원본 `actor.onnx` 추론, residual 계산, 관절·그리퍼 속도 제한과 모터 전송은
C++에서 수행하고 ROS 영상·충돌 검사·단계 전환은 이 패키지에서 재사용한다. 구형
33차원 `omx_rl_control_cpp`와는 별도다. 설치·로컬 검증·추후 로봇 배포 순서는 해당 문서를 따른다.

카메라와 C++ ONNX/OpenCR 런타임을 묶은 진입점은 다음과 같다. 기본 모드는 읽기 전용이다.

```bash
ros2 launch omx_turtlebot3_runtime real_robot_cpp.launch.py
```

런치는 선택된 Python 환경에서 모델 체크섬·실제 ONNX 추론·URDF·충돌 장면을 먼저 검사하고,
통과하면 카메라와 런타임을 시작한다. `python_executable:=/경로/가상환경/bin/python` 또는
`OMX_CPP_PYTHON`으로 Python 환경을 지정한다. 워크스페이스의 `.venv_omx_cpp`가 있으면 자동 선택한다.
카메라는 `v4l2_camera`가 필요하며 기존 영상 발행기를 사용할 때만 `start_camera:=false`로 실행한다.

실제 구동은 `mode:=execute config:=/검증된/실물보정.yaml`을 추가한다. 현재 기본 설정으로는
실행 모드가 모터 통신 시작 전에 거부된다. 프로세스 시작 후에도 집기는 별도의
`/omx_v6/request` 및 현장 `/omx_v6/deadman` 신호를 요구한다. 런치가 이를 자동 생성하지 않는다.

C++ 실행 모드의 시작 순서는 `WAIT_DEADMAN → MOVING_STAY → READY → MISSION`이다.
`mp_control/launch/aruco_pick_place.launch.py`처럼 Stay 자세를 먼저 취한다.
목표는 기존과 같은 `[0.104311, 0.027612, -0.001534, -1.638291]` rad다.
관절 제한·충돌 경로 검사 후 C++에서 최소 3초의 동시 관절 궤적을 만들고, 속도 0.12 rad/s와
가속도 0.3 rad/s²에 맞춰 이동 시간을 늘린다. 위치 오차 0.025 rad 이하, 속도 0.03 rad/s 이하가
0.3초 유지되어야 `READY`가 된다. 초기화 중 요청은 거부하며, deadman 만료·취소·추종 실패·
60초 도달 시간 초과에는 정지한다. `READY` 대기 중에도 C++ watchdog과 Stay 유지를 계속한다.
토크 OFF라면 실행 모드에서만 현재 목표와 저속 프로파일을 먼저 설정한 뒤 팔 토크를 켠다.
기존 ROS 하드웨어 제어기를 같이 띄우지 않으며 직렬 포트 소유자는 하나다.
통합 런치의 실행 모드는 한 임무가 끝나면 최종 위치 유지 명령을 보낸 후 런타임과 카메라를 종료한다.
직접 실행 시에는 `--exit-after-mission`으로 같은 동작을 선택한다.

모터·ROS를 열지 않고 모델과 설정만 검사하는 명령은 다음과 같다.

```bash
python -m omx_turtlebot3_runtime.node --backend cpp_onnx --check-startup
```

`STARTUP_CHECK_PASSED`는 모델·기구학 검사 결과이며 실물 카메라·접촉·집기 성공 판정이 아니다.
실행 준비 여부는 `execution_config_ready`와 `commissioning_issues`를 함께 확인한다.

## 구성과 입력

- `core.py`: 물체 ID와 관측 유효기간, 69차원 관측, 제한된 보정량, 집기·안착 추정.
- `planning.py`: 학습 장면의 FK·IK·경로 충돌 검사. `mj_forward`만 호출하며 물리 시뮬레이션의
  접촉값이나 물체 위치를 실물 관측으로 쓰지 않는다.
- `mission.py`: 인지 → 열기 → 접근 → 집기 → 빼기 → 오른쪽 회전 → 내리기 → 놓기 → Stay.
- `opencr.py`: OpenCR ID 200의 관절·그리퍼 제어. 바퀴 명령, 토크 변경, EEPROM 쓰기 없음.
- `vision.py`: 기존 `aruco_eef_tracker`의 사전·검출기 도우미를 재사용하는 다중 물체 PnP.
- `node.py`: ROS 요청·취소·현장 활성 신호, 시간 동기화, 로그 및 오류 시 정지.
- `startup.py`: C++ Stay 초기화 순서와 임무 요청 차단·전환.

실물 마커는 `DICT_4X4_50`, 검은 정사각형 한 변 40 mm, ID 0·1이다. ID 0은 모델의 첫 슬롯
(학습 라벨 1), ID 1은 두 번째 슬롯(학습 라벨 2)으로 연결한다. 화면에서 큰 마커를 대신
선택하거나 X 좌표를 고정하지 않는다. 입력 자세는 마커 중심에서 50 mm 물체 중심으로 변환한다.
물체 앞면의 부착 위치·인쇄 방향도 보정 대상이다.

관절 속도는 연속 엔코더와 OpenCR 시간 차로 계산한다. 그리퍼 두 손가락 위치는 단일 구동
엔코더로 대칭 추정한다. 전류는 원시 레지스터 값으로 기록하며 N·Nm 단위 힘으로 표기하지 않는다.

## 실물 mp_control 좌표 계약 반영 (2026-11-21)

- 기본 설정은 로봇의 설치된 Xacro를 `mp_control/real_pick_place.launch.py`의 카메라
  인자로 전개한 `assets/robot_real.urdf`를 사용한다. SHA-256을 검증하며 손목→카메라
  장착 변환과 광학 프레임 변환을 직접 읽는다. 장착 Y축 회전은 +90도이고 광학 프레임
  위치에는 학습 렌더러의 별도 57 mm 오프셋을 적용하지 않는다.
- URDF의 관절 체인과 학습 모델의 움직이는 팔 체인을 여러 자세에서 대조한다.
  로봇 base_footprint와 학습 world 사이의 변환은 `policy_from_base`로 명시한다.
  이것은 좌표계 변환이지 실제 선반·팔로워 배치를 검증했다는 의미가 아니다.
- `mp_control_equivalent`는 최종 controller 목표→joint3 사전 반전→재반전을 같은
  최신 관절 참조값으로 처리한다. joint4는 이미 계획된 최종 각도이므로 이중 보정하지 않는다.
  0.20 rad 변화량과 기존 raw/controller 범위를 넘으면 조용히 잘라내지 않고 거부한다.
- 이 경로는 **기존 변환식의 프로세스 내부 동등 구현**이다. 기존 ROS arm_controller나
  mp_control 전체 런치를 실행하는 것은 아니며, 최종 출력은 기존의 제한된 OpenCR
  전송기를 사용한다. 따라서 기존 노드와 동시에 실행하지 않는다.
- 이 변경으로 검증 완료 플래그나 집기·안착 전류 임계값을 임의로 설정하지 않는다.

카메라 런치가 켜진 상태에서 아래 명령은 최신 영상·엔코더로 모델 추론과 전체 경로를
검사하고 종료한다. 실행 모드와 함께 사용할 수 없고 모터를 arm하지 않는다.

```bash
/home/a/turtlebot3_ws/.venv_omx_runtime/bin/python -m omx_turtlebot3_runtime.node \
  --check-plan-id 0 --duration 15 --log-dir /tmp/omx_v6_plan_unique
```

`MODEL_PLAN_CHECK`의 `actor_action`은 추론 결과일 뿐 실제 관절 명령이 아니다.
`plan_status`가 통과해도 실물 접촉·안착 및 장면 검증을 대신하지 않는다.

## 실물 신호 기반 집기와 안착

### 전체 팔 협조 전방 전개 시험

`python -m omx_turtlebot3_runtime.forward_trial --log-dir /tmp/고유_로그_경로`는
현재 Stay 근처 자세에서 높이·그리퍼 pitch를 유지하면서 로봇 전방 X로 10 mm 이동하는
전체 관절 경로를 검사한다. `--execute-forward`를 명시하면 확인된 경로를 약 8초에 걸쳐
한 번 실행하고 위치를 유지한다. joint2·3·4를 함께 보간하며 joint1도 직선 경로에 맞춰
보정한다. 단독 관절 시험이 아니다. 이동 후 자동 복귀·집기·반복은 하지 않는다.

이것은 실제 팔의 협조 전개·추종을 확인하는 IK 기준 경로 시험이며 **PPO 제어 또는 집기
성공 시험은 아니다**. 전체 임무 보정 플래그와 접촉 임계값은 변경하지 않는다. 관절 총 변화량
0.12 rad, 명령 속도 0.03 rad/s, 전송 권한 15초와 경로 근방의 encoder 목표만 허용한다.
그리퍼·바퀴·토크·프로파일 쓰기는 차단하며 최신 영상, 실제 관절·전류·전압·base 정지를
확인한다. 오류나 `/omx_v6/cancel` 요청 시 현재 위치 유지 후 종료한다. 하드웨어 비상정지를
대신하지 않는다. OpenCR을 사용하는 다른 런타임은 먼저 종료해야 한다.

### 관절 3 제한 시운전 (집기 아님)

`python -m omx_turtlebot3_runtime.probe --log-dir /tmp/고유_로그_경로`는 최신
엔코더·양쪽 마커 관측으로 현재 Stay 근처에서 joint3를 22 encoder tick
(약 1.934도) 움직이는 구간을 읽기 전용으로 검사한다. 기존 저속 모터 프로파일도 확인한다.
전체 집기 경로 통과 또는 실물 보정 완료를 뜻하지 않는다.

현장에서 주변을 비우고 즉시 정지할 수 있는 상태에서 `--execute-probe`를 명시한
경우에만 같은 제한 구간을 한 번 시험한다. v6 추론과 기준 경로 보정식을 사용하지만,
joint1·2·4 출력은 차단하고 joint3만 단방향·최대 1.934도로 제한한다. 계획 속도는
0.02 rad/s, 전송 상한은 0.03 rad/s이며 3초 후 현재 위치를 유지하고 종료한다.
전송 권한 자체도 4초로 제한한다. 자동 반복·자동 원상복귀는 하지 않는다.

이 별도 시험은 그리퍼·바퀴·토크·모터 프로파일을 쓸 수 없다. 과전류, 관절 추종 이상,
다른 관절 또는 그리퍼 이동, 카메라/FK 관측 불일치, 마커 관측 만료, 통신 지연 또는
`/omx_v6/cancel` 요청 시 중단한다. 하드웨어 비상정지를 대신하지 않는다.
OpenCR을 사용하는 읽기 전용 런타임도 먼저 종료해야 한다. 전체 임무의 보정 플래그와
집기·안착 임계값은 변경하지 않으며 `PROBE_DONE`은 **집기 성공 신호가 아니다**.

집기는 단계적으로 판정한다. 닫기 명령 중 그리퍼가 50 mm 물체 폭에 해당하는 위치에서
멈추고 전류가 임계값 이상 유지되며, 선택한 물체가 그리퍼 가까이에 보여야 접촉 후보가 된다.
이때는 짧은 들어올림만 허용한다. 신선한 영상 여러 장에서 물체가 실제로 함께 올라가고
그리퍼와의 상대 위치가 유지되어야 회전·운반으로 넘어간다. 전류나 벌어짐 증거가 사라지면 정지한다.

안착은 그리퍼가 실제로 열리고 전류가 감소한 뒤, 물체의 회전된 전체 바닥 면적이 검증된
팔로워 상판 안에 있고 바닥 높이·선속도·각속도가 안정적인 영상이 연속 확인되어야 성립한다.
명령 완료, 기다린 시간, 카메라에서 사라짐만으로 성공 처리하지 않는다. 마커가 가려져 들어올림
또는 안착 증명을 할 수 없으면 시간 제한 후 정지하며 임계값을 자동 완화하지 않는다.

이 판정은 양쪽 손가락 접촉 센서나 적재면 센서의 직접 측정이 아니다. 학습 때 접촉 두 비트를
실물 추정값으로 대체하므로 관측 분포가 달라진다. 실물 데이터로 오검출·미검출과 전체 임무를
검증한 뒤, 필요하면 해당 관측 정의로 재학습해야 한다.

## 배포와 읽기 전용 실행

호스트 소스는 `/home/ktj/omx_turtle_ws/src/omx_turtlebot3_runtime`, 로봇 소스는
`/home/a/turtlebot3_ws/src/omx_turtlebot3_runtime`이다. 기존 실물 제어 런치·자동 Stay·ArUco
브릿지는 함께 실행하지 않는다. 이 제어기는 OpenCR 직렬 장치를 독점한다.

로봇 전용 가상환경은 시스템 ROS·PyTorch를 재사용하고 MuJoCo 3.10.0을 별도 설치한다.
아래 Python 모듈 실행을 사용한다. `ros2 run`의 시스템 Python에는 MuJoCo가 없을 수 있다.

```bash
source /opt/ros/humble/setup.bash
source /home/a/turtlebot3_ws/install/setup.bash
export ROS_DOMAIN_ID=25
/home/a/turtlebot3_ws/.venv_omx_runtime/bin/python -m omx_turtlebot3_runtime.preflight \
  --seconds 3 --output /tmp/omx_preflight_unique.json
/home/a/turtlebot3_ws/.venv_omx_runtime/bin/python -m omx_turtlebot3_runtime.node \
  --duration 10 --log-dir /tmp/omx_runtime_unique
```

출력 파일과 로그 폴더는 기존 경로를 덮어쓰지 않는다. 기본 추론은 검증된 TorchScript CPU이며
`--device cuda`를 명시할 수 있다. `--backend onnx`는 ONNX Runtime이 설치된 환경에서 사용하며
누락된 백엔드로 자동 대체하지 않는다. 모든 모델 파일의 체크섬을 검사한다.

카메라는 Jieli HCAM0의 `video-index0`, YUYV 320×240을 사용한다. 기존의 비구동 런치로
RGB 영상과 보정 정보를 공급할 수 있다. Orbbec Astra/depth는 사용하지 않는다.

```bash
ros2 launch aruco_eef_tracker eef_aruco_v6_dual.launch.py start_camera:=true \
  camera_info_url:=file:///home/a/turtlebot3_ws/src/manipulator_control/calibration/eef_camera/eef_usb_camera.yaml
```

이 런치의 단일 마커 Pose 토픽을 제어기에 바로 넣지는 않는다. 제어기는 같은 영상에서 두 ID와
PnP 오차를 다시 확인하고 영상 취득 시각의 관절값으로 변환한다. 원래 제어기의 자동 시작
토픽과 격리된 `/omx_v6/` 토픽만 사용한다.

## 실물 구동 전 검증과 실행 조건

`config/runtime.yaml`의 `commissioning` 항목은 기본 false이고 전류 임계값은 null이다.
실측 자료 없이 true나 임의 임계값을 넣지 않는다. 별도 보정 설정 파일을 만들어 `--config`로 전달한다.

1. 각 관절 영점·방향과 실제 Stay를 확인한다. C++ 실행 모드의 초기 Stay 이동도 검증된 매핑과 경로를 요구한다.
2. 실제 카메라 렌즈의 link5 기준 변환, 마커 부착 변환, 카메라 보정을 검증한다.
3. 선반·상판·팔로워·로봇의 상대 배치와 충돌 모델을 일치시킨다. 제공 값은 학습 장면 기준이다.
4. 빈 닫힘·물체를 잡은 상태·미끄러짐·안착 데이터를 구분해 전류·벌어짐·영상 임계값을 검증한다.
5. 정지·통신 단절·프로세스 종료 시 동작을 현장에서 검증한다. OpenCR의 기존 heartbeat 단절은
   팔 토크 해제나 팔 정지를 보장하는 하드웨어 비상정지가 아니다. 전원 차단 수단을 준비한다.
6. 근거 파일 경로를 `evidence_directory`에 기록하고 모든 검증 항목이 충족된 설정만 실행한다.

구동은 `--execute`, 검증된 설정, Stay 초기화 성공, 두 물체의 신선한 관측, 유효한 요청,
지속적인 현장 활성 신호를 모두 요구한다. 기본 관절 속도 상한은 초기 검증용 0.12 rad/s다.
요청은 `std_msgs/msg/String`의 `{"request_id":"고유값","object_id":0}` 형식으로
`/omx_v6/request`에 보낸다. object_id는 실물 ID 0 또는 1이다.
`/omx_v6/deadman`에는 현장 준비 상태를 나타내는 Bool true가 0.5초 이내 간격으로 들어와야 한다.
false 또는 수신 만료 시 정지한다. Stay 초기화는 deadman이 들어온 뒤 진행하며 임무의 자동 시작·재시도는 없다.

`/omx_v6/cancel`의 Bool true는 정지 요청이다. 정지는 새 경로를 멈추고 가능한 경우 현재 관절
위치를 유지하며, 잡은 물체를 떨어뜨리지 않도록 그리퍼를 자동으로 열거나 토크를 끄지 않는다.
통신 자체가 끊기면 이 소프트웨어 정지가 전달되지 않을 수 있으므로 현장 비상정지가 필요하다.
