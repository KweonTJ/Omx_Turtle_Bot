# Leader visual mesh provenance

- Source video: user-provided `20261013_204330.mp4`, 2026-10-13.
- `lower_plate.stl`, `camera_plate.stl`, `upper_plate.stl`: identical assemblies
  of **three half plates on every level**, as clarified by the user. One actual
  half plate is extracted from ROBOTIS-derived `../turtlebot3_waffle_pi/base.stl`
  and reoriented without stretching (unit conversion only): two opposing halves
  make the front octagon; the third half meets its narrow rear edge. The final
  rear half is absent. Centres/yaws in assembly mm/degrees are
  `(32,-32,+90)`, `(32,+32,-90)`, `(-64,0,180)`.
  Each assembly has 7,746 triangles and bounds about 201.547 × 137.547 × 9 mm.
  This supersedes the initial, incorrect 8-part lower/4-part upper scaled plates.
  It also supersedes the incorrect three-parallel-halves intermediate revision.
  Retain upstream ROBOTIS attribution
  and this repository's Apache-2.0 package license. Not a new factory CAD release.
- `sprocket.stl`: plastic wheel component extracted from the repository's
  ROBOTIS-derived `../turtlebot3_waffle_pi/left_tire.stl`, mm converted to m.
- `motor_left.stl`, `motor_right.stl`: original motor case, eight case screws and
  connector from `base.stl`, 1,492 triangles each. Four URDF instances (front/rear
  on both sides); user confirmed all four are driven. Output-axis origin uses
  source shaft centre `(64,+/-144,23.25)` mm. The Z=23.25 mm shaft centre is
  checked by sectioning the source mesh; the old rounded Z=23 offset is corrected.
  Rear cases face inward (180-degree
  pitch). Exact motor model/physical bracket/hub dimensions are not confirmed.
- `track.stl`: locally generated approximate ICT-01-style links. Latest axle
  centres X=0/-138.5 mm supersede +34/-162, 0/-128 and 0/-150 mm estimates.
  Front matches stock Waffle X. User measured ~68 mm of EMPTY SPACE between
  the facing CASE surfaces, not between shaft centres. Source case reaches
  35.25 mm inward from each shaft: axle spacing = 68 + 2*35.25 = 138.5 mm.
  The 41 visual subdivisions give an approximately 12.12 mm illustrative pitch.
  They do not assert real link count, pitch or measured bolt coordinates.
  Conservative collision size 217.5x42x79 mm, centred at X=-69.25 mm,
  includes rotated tread corners. Width, curve radius and rib thickness retained.
- All generated STL units: **metres**, URDF scale 1. Original arm STL files remain
  unchanged and continue using mm-to-m scaling.
- User-confirmed connecting support lengths: **40 / 55 / 55 mm**. These are
  not plate-centre spacings. Xacro seats supports between the unchanged 9 mm
  plate envelopes, giving base-relative plate centres 4.25/53.25/117.25/181.25 mm.
  Arm origin follows its plate to 181.75 mm with the prior relative offset.
  Relative sensor/arm extrinsics and the default hardware profile are unchanged.
- `scripts/generate_leader_meshes.py` reproduces these files with numpy/trimesh.
  Runtime URDF/RViz does not need those Python dependencies.
- `opencr_pcb.png`, `jetson_pcb.png`: original procedural inspection textures,
  generated by `scripts/generate_leader_textures.py` (Pillow). Silkscreen and
  traces are illustrative, not manufacturer artwork or electrical schematics.
  These are URDF texture materials on UV-mapped box primitives, not on STL.
  The remaining STL visuals use distinct opaque URDF colors; tread relief,
  board ports and cooler fins provide geometric surface detail. No PBR claim.
  The exported URDF groups materials into identity fixed child links to work
  around installed Humble RViz 11.2.29 flattening all visuals to the first
  material in each link. Use export_leader_urdf.py or the leader preview launch.
- Electronics visual footprints: OpenCR 105 x 75 mm, Jetson reference carrier
  100 x 79 mm. Layout, 6 mm standoffs and 35 mm Jetson cooler assembly envelope
  are display approximations, not an exact measured devkit/cooler assembly.
  See ROBOTIS OpenCR manual and NVIDIA reference-kit hardware documentation:
  https://emanual.robotis.com/docs/en/parts/controller/opencr10/
  https://docs.nvidia.com/jetson/orin-nano-devkit/user-guide/latest/hardware_layout.html
  https://developer.nvidia.com/blog/develop-ai-powered-robots-smart-vision-systems-and-more-with-nvidia-jetson-orin-nano-developer-kit/

This is a visual reconstruction, not a calibrated mass/contact/slip model.
Belts are fixed; each motor has a coaxial rotating hub/sprocket child. Four display
rotors mimic the existing two side wheel states; this is NOT independent four-
encoder telemetry. Latest user measurement is **95 mm empty space between the
LEFT/RIGHT INNER CASE FACES**, not axle centres. Each source case reaches 45 mm
inward from its shaft: axle separation = 95 + 2*45 = 185 mm. Final belt/motor
centres Y=+/-92.5 mm replace the +/-98 mm hole-alignment estimate. Motors,
coaxial wheels/hubs and belts all move inward 5.5 mm per side; no mesh rescaling.
42 mm belt width gives overall width 227 mm and plate-edge gap ~2.7265 mm.
The case/horn still projects ~19.1 mm beyond the plate. These are calculated
dimensions using the measured case gap, not additional physical measurements.
The four source case holes remain 24 x 12 mm, at `(36/60,+/-110/122)` mm.
Their extraction is checked, but at the new measured placement the inner hole
row is at |Y|=58.5 mm, NOT the earlier assumed plate row 64 mm. Exact fastening
and spacers are uncalibrated. No motor-ID, driver or odometry changes.
